# Integrated Road Dyno Implementation Plan

> **For agentic workers:** Use the host's available task-by-task implementation workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One APK with setup, recording and automatic analysis after STOP.

**Architecture:** Existing foreground service continues lossless raw recording. Room holds calculation inputs; the Android-independent engine processes the completed trace; Compose presents reproducible results.

**Tech Stack:** Kotlin, Compose, Room, Coroutines, JUnit, GitHub Actions.

## Global Constraints
One application ID com.roaddyno.app; user-controlled START/STOP; raw samples never altered; GPS_PROVIDER maximum requested rate; no manual phase marking.

### Task 1: Persist setup and connect recording
- [x] RunConfiguration validates mass and paired RPM calibration.
- [x] SessionEntity, RoadDynoDatabase migration and repository store inputs, preserving previous sessions.
- [x] MainViewModel and MeasurementService pass validated configuration into session creation.
- [x] MainActivity routes completion to result once; history reopens result with stored parameters.

### Task 2: Physical engine and result presentation
- [x] DynoEngine calculates energy/time slope and matched-speed coast losses; no 20 s truncation, no scoring multiple pulls.
- [x] DynoScreens shows setup, curves and maxima with units, common coast range, and recalculation.
- [x] DynoCsvWriter produces derived export with algorithm and input metadata.
- [x] RoadDynoPhysicsTest covers known 1000 kg, 0.5 m/s², 0.2 m/s² coast at 15 m/s: 7.5 + 3 = 10.5 kW, 33.423 Nm at 3000 rpm; 1/20 Hz; mass scaling; >20 s pull; absent/partial coast; multiple pulls; raw immutability; gaps; invalid calibration; CSV escaping.

### Task 3: Verify and distribute
- [ ] Run `gradle :app:testDebugUnitTest :app:assembleDebug --no-daemon` in CI; expect all JUnit tests and APK assembly to pass.
- [ ] Review configuration loading, STOP-to-result and migration source paths; inspect built APK package/version.
- [ ] Store code in feature branch/PR and deliver installable APK.

No unresolved product decisions for this increment. Physical installation, background recording and numerical comparison with the user's Dynomet require device testing.
